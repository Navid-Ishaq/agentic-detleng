System anatomy

The useful system is the front door.
The NLP mechanics sit underneath.

Open the technical layer only when you want to inspect how the language was tokenized, normalized, tagged and mapped into spans. These are implementation mechanics, not the business proposition.

Why keep stemming and lemmatization here? They are useful technical comparisons for some classic NLP/search pipelines, but they are not the commercial value of this system. The business value is reliable language-to-structure conversion with validation before downstream action.

Break it

The dangerous failures are
business failures, not vocabulary mistakes.

A system can extract several correct words and still produce an unsafe action. These experiments put the operational failure first.

Failure 01 · negation

“Do not send before Friday.”

Items and dates may be extracted correctly while the critical relationship is lost.

Run the test.
Failure 02 · missing field

“Move the order to Glasgow.”

The intended action is clear, but the order identifier is missing. Execution must stop.

Run the test.
Failure 03 · ambiguity

“Notify Jordan in Paris.”

Names can support several interpretations. Silent certainty is a control failure.

Run the test.
Failure 04 · conflict

Two destinations, one order.

Conflicting instructions should become a clarification request, not a guessed tool call.

Run the test.

Production control model

Never “understand” and execute
in one uncontrolled jump.

For consequential workflows, language interpretation is only the first stage. Required fields, ambiguity, permissions and business rules must be checked before a real action is allowed.
